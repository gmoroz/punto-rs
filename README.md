# punto-rs

*Keyboard layout corrector daemon for Linux/Wayland: typed `ghbdtn` instead of
`привет`? Hit a hotkey — the word is retyped in the right layout. A Punto
Switcher / Easy Switcher alternative built on evdev/uinput, based on replaying physical keys between two layouts. Docs below are in Russian.*

Исправление раскладки уже набранного текста для Linux/Wayland — замена Punto
Switcher и Easy Switcher. Набрал `ghbdtn` вместо `привет` и пробел — слово
само перенабирается в правильной раскладке. `Insert` исправляет слово вручную
и отменяет автоисправление.

Автоисправление работает в KDE Plasma с парой раскладок `us,ru`: активную
раскладку демон узнаёт по session D-Bus (`org.kde.keyboard`). Слово
исправляется, только если в другой раскладке оно есть в словаре, а на экране —
нет, и модель букв считает его заметно правдоподобнее: ложное исправление хуже
пропуска. Слова короче трёх букв и с цифрами не трогаются. На размеченном
наборе (`cli/tests/data/layout_cases.tsv`, отложенная часть) — 0 ложных
исправлений на 360 словах, которые трогать нельзя (обычные слова, термины,
код, транслит), и 190 из 200 исправленных слов в чужой раскладке.

## Как это работает

Демон хранит не символы, а **скан-коды** нажатых клавиш. Чтобы исправить
раскладку, достаточно стереть набранное, переключить раскладку системной
комбинацией и переиграть те же самые физические клавиши — система сама
отдаст буквы другого алфавита.

Ключевое отличие от Easy Switcher: вне коррекции клавиатура **не
перехватывается**. Easy Switcher забирал устройство себе и переизлучал каждое
нажатие — на этом он терял буквы при быстром наборе. Здесь чтение пассивное.
Только на время перенабора демон захватывает клавиатуры (`EVIOCGRAB`), чтобы
набор не смешался с исправлением, а нажатое за это время переигрывает сразу
после него.

Плата за это — горячая комбинация долетает и до активного приложения. Чтобы
она не вызывала побочного действия, её можно привязать в настройках оконного
менеджера или композитора к пустой команде.

## Установка

Готовые статические сборки для `x86_64` публикуются в
[GitHub Releases](https://github.com/gmoroz/punto-rs/releases). Скачать
последнюю сборку для текущей архитектуры и проверить её checksum:

```sh
ARCH="$(uname -m)"
case "$ARCH" in
  x86_64) ;;
  *) echo "Архитектура $ARCH пока не поддерживается готовыми сборками" >&2; exit 1 ;;
esac

BASE_URL="https://github.com/gmoroz/punto-rs/releases/latest/download"
curl -fLO "$BASE_URL/punto-rs-linux-$ARCH.tar.gz"
curl -fLO "$BASE_URL/punto-rs-linux-$ARCH.tar.gz.sha256"
sha256sum -c "punto-rs-linux-$ARCH.tar.gz.sha256"
tar -xzf "punto-rs-linux-$ARCH.tar.gz"
cd punto-rs
```

Установить файлы из распакованного архива:

```sh
sh scripts/install.sh
~/.local/bin/punto-rs --check-config
~/.local/bin/punto-rs --check-session
systemctl --user daemon-reload
systemctl --user enable --now punto-rs
```

Root не нужен: демон работает как пользовательский сервис systemd и
запускается вместе с `graphical-session.target`. Доступ к `/dev/input/*` и
`/dev/uinput` даёт группа `input`; если пользователь в неё не входит, один раз
выполните `sudo usermod -aG input "$USER"` и перелогиньтесь. Нужны
systemd-logind и системная D-Bus. Коррекция разрешена только в локальной
графической сессии на `seat0`, принадлежащей тому же пользователю: TTY, экран
входа, удалённые сессии и сессии других пользователей её не получают.

Файлы ставятся в домашний каталог: бинарник в `~/.local/bin/punto-rs`,
конфиг в `~/.config/punto-rs/config.conf` (или `$XDG_CONFIG_HOME`), unit в
`~/.config/systemd/user/punto-rs.service`. Установщик сохраняет существующий
конфиг, а новый образец кладёт в `config.conf.example`. Сервис он не запускает
и не перезапускает. При обновлении проверьте конфиг через
`punto-rs --check-config`, затем выполните `systemctl --user daemon-reload` и
`systemctl --user restart punto-rs`. Для отката установите предыдущий архив и
перезапустите сервис тем же способом.

Удаление с сохранением настроек:

```sh
systemctl --user disable --now punto-rs
rm ~/.local/bin/punto-rs ~/.config/systemd/user/punto-rs.service
systemctl --user daemon-reload
```

### Сборка из исходников

Нужны rustup и C-компилятор для vendored libdbus. Код крейта лежит в `cli/`,
версия Rust закреплена в `cli/rust-toolchain.toml`, и rustup подтягивает её сам:

```sh
make install
cd cli && cargo build --release --locked
```

Установка из исходников: `sh cli/scripts/install.sh cli/target/release/punto-rs`.

Бинарный файл появится в `cli/target/release/punto-rs`.

## Использование

| Действие | Клавиши |
|---|---|
| Автоисправление слова | пробел после слова |
| Исправить последнее слово / отменить автоисправление | `Insert` |
| Исправить всю фразу | `Super+Insert` |
| Пауза / возобновление | `Super+Pause` |

Коррекция начинается только после отпускания физических клавиш. Горячая
комбинация должна быть нажата без посторонних клавиш. `Shift+Insert` не
перехватывается программой и сохраняет своё системное действие.

Буфер сбрасывается на `Enter`, `Tab`, `Shift+Tab`, навигации (стрелки,
`Home`, `Delete`), командах с `Ctrl`/`Alt`/`Super`, системной комбинации смены
раскладки и клике мышью. Дополнительные причины сброса: автоповтор клавиши,
подключение/отключение устройства, потеря evdev-событий, пауза и 30 секунд
без ввода.

Набор во время коррекции не прерывает её: клавиатуры захвачены, нажатия
копятся и переигрываются после перенабора. Если клавиатуру уже захватил другой
процесс или клавиша ещё нажата, коррекция пропускается. Клик, смена сессии
или устройства прерывают перенабор: демон отпускает синтетические клавиши и
сбрасывает буфер, **уже выполненные удаления и нажатия не откатываются**. При
ошибке записи сервис завершает работу после попытки отпустить клавиши; systemd
запускает его заново с пустым буфером.

При блокировке, смене сессии, подготовке ко сну и ошибках logind коррекция
приостанавливается, история сбрасывается. Старые события из очереди не
используются в новой сессии. Изменения отслеживаются через D-Bus-сигналы и
периодическую проверку; снимок logind старше двух секунд не разрешает ввод.
Это зависит от корректной передачи `LockedHint` композитором и не является
гарантией мгновенного определения блокировки.

Клики отслеживаются потому, что переход между полями ввода мышью иначе не
виден демону: без этого исправление в новом поле вставило бы хвост из
предыдущего. Отключается опцией `track-mouse=no`.

## Настройка

Конфиг — `~/.config/punto-rs/config.conf`, формат `ключ=значение`.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `auto-switch` | `yes` | исправлять слово само на пробеле (KDE Plasma, `us,ru`) |
| `hotkey` | `insert` | комбинация исправления последнего слова |
| `phrase-hotkey` | `super+insert` | комбинация исправления всей фразы |
| `pause-hotkey` | `super+pause` | приостановить/возобновить работу с очисткой буфера |
| `layout-switch` | `super+space` | системная комбинация смены раскладки |
| `key-delay` | `1` | пауза между событиями, 1–100 мс |
| `post-backspace-delay` | `0` | пауза после стирания, 0–2000 мс |
| `switch-delay` | `120` | предел паузы после смены раскладки, 0–2000 мс; в KDE пауза заканчивается по сигналу о новой раскладке |
| `devices` | пусто | клавиатуры по именам; пусто — автоопределение |
| `max-strokes` | `512` | предел буфера, 1–4096 нажатий |
| `track-mouse` | `yes` | сбрасывать буфер по клику мышью |
| `session-guard` | `yes` | проверять локальную сессию через logind |
| `buffer-timeout` | `30000` | сброс после простоя, 1000–300000 мс |

Для GNOME штатное переключение — `layout-switch=super+space`. В KDE Plasma
6.6 использовалось `layout-switch=super+alt+37` (`Meta+Alt+K`, где `37` —
скан-код K). Сначала добавьте две раскладки в настройках рабочего окружения
и проверьте их переключение обычной клавиатурой. Версии окружений, условия
и результаты проверки указаны в [отчёте приёмки](cli/docs/release-validation.md).

Клавиши задаются именем (`insert`, `pause`, `scrolllock`, `capslock`, `menu`,
`rightctrl`, `f1`…`f12` и другие) либо скан-кодом из `input-event-codes.h`.
Комбинации записываются через `+`, например `super+insert`. Последняя клавиша —
триггер, перед ней допустимы только модификаторы. Числовые коды ограничены
диапазоном 1–255; повторяющиеся клавиши и совпадающие комбинации запрещены.
Ошибки значений, неизвестные и повторяющиеся параметры останавливают запуск.
Явно заданный через `-c` отсутствующий файл — ошибка. При ручном запуске без
`-c` отсутствие стандартного файла включает настройки по умолчанию; systemd
проверяет наличие и корректность файла перед запуском.

COSMIC 1.0.9 не обновляет `LockedHint` при блокировке экрана. Поэтому
при включённом `session-guard` коррекция в сессиях COSMIC запрещена;
в этом релизе COSMIC не поддерживается. Отключение защиты не является
исправлением этой несовместимости.

`session-guard=no` предназначен для изолированных тестовых сред или систем
без logind: автоматическая защита при блокировке/смене сессии отключается.
Пауза по хоткею остаётся доступной.

Список устройств: `punto-rs --list-devices`.
Скан-коды клавиш: `sudo showkey` или `wev`.

## Тесты

```sh
make full-check

# Только в отдельной тестовой VM с работающим сервисом и стандартным конфигом:
cd cli && cargo build --release --example e2e --locked
sudo target/release/examples/e2e --live-session
```

`make full-check` запускает fmt, Clippy, cargo deny, cargo machete, тесты
nextest с порогом покрытия, проверку установщика и проектные гейты.

Сквозной тест создаёт виртуальную клавиатуру, печатает на ней слово не в той
раскладке, жмёт горячую клавишу и проверяет по выходному устройству демона,
что во время набора тот молчал, а по нажатию стёр и перенабрал ровно то, что
нужно, включая порядок отпускания всех клавиш. События уходят в активное окно.
Этот пример не запускается командой `cargo test`: автоматические тесты
проверяют основной цикл с подменённым устройством, ошибки записи, отмену,
сессии и конфиг без доступа к клавиатуре. Итоговый текст и реакция приложений
проверяются отдельно по [матрице приёмки](cli/docs/release-validation.md).

GitHub Actions на каждом push и pull request запускает форматирование, Clippy,
юнит-тесты и собирает статические архивы для `x86_64`. При push
тега `vX.Y.Z`, совпадающего с версией в `cli/Cargo.toml`, эти архивы и их SHA-256
checksums автоматически добавляются в GitHub Release.
Перед созданием тега подготовьте заметки `cli/docs/releases/vX.Y.Z.md`:
workflow использует этот файл как описание релиза.

## Диагностика

```sh
punto-rs --check-config
punto-rs --check-session
systemctl --user status punto-rs
journalctl --user -u punto-rs -f
punto-rs -v   # с остановленным сервисом
```

Первые буквы выходят в старой раскладке — увеличьте `switch-delay`.
Ничего не происходит — проверьте состояние сессии, паузу и совпадение
`layout-switch` с системной комбинацией смены раскладки.
Второй экземпляр не запускается: блокировка находится в `$XDG_RUNTIME_DIR/punto-rs/daemon.lock`.
Файл остаётся после остановки, но сама блокировка освобождается ядром;
удалять файл для повторного запуска не нужно.

## Ограничения

- Раскладка переключается инжектом системной комбинации, поэтому она должна
  быть настроена в самой системе и переключать ровно между двумя раскладками.
- Поддерживаемая модель — один печатный символ на нажатие основного блока
  клавиатуры, две раскладки без IME, Compose и dead keys. AltGr и автоповтор
  сбрасывают буфер; раскладки с такими механизмами требуют отдельных проверок.
- Демон не видит текст на экране: если править курсором в середине строки,
  буфер и экран разойдутся. Такие случаи гасятся сбросом буфера на навигации
  и на клике мышью.
- Тап по тачпаду вместо физического клика не виден на уровне evdev — его
  синтезирует уже libinput. Буфер сбросит только настоящее нажатие тачпада
  или кнопки мыши.
- Фокус, парольные поля, автозамены и изменение текста самим приложением
  неизвестны демону. Перед чувствительным вводом включайте паузу; без
  интеграции с композитором автоматически исключить такие поля нельзя.
- Перенабор не атомарен относительно физического ввода и смены фокуса.
  Отмена ограничивает дальнейший инжект, но не восстанавливает исходный текст.
